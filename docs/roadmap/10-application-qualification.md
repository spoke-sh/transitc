# 10. Whole-application and performance qualification

Status: Planned

Prerequisites: the required profiles of milestones
[5](05-typed-composition-and-sql.md), [6](06-workspaces-and-developer-tooling.md),
[7](07-migrations-and-definition-evolution.md), [8](08-protected-workflows.md)
and [9](09-deterministic-tests-and-replay.md), plus their compatible Transit owners.
Measurement design and fixture inventory can start earlier.

Demonstrate that one attributable compiler/runtime combination builds, migrates
and tests the complete application workload, with measured authoring and execution
cost. This expands former M12 P6, its completion journeys and completion-plan H.
It is distinct from [milestone 4](04-documentation-and-qualification.md), which
qualifies the extracted tool's documentation, hosts and distribution.

## Workload and source basis

The original proposal used a 3,513-line, seven-migration Platform baseline across
`auth`, `catalog`, `tenancy`, `networking`, `deployments` and `publication`, with
26 commands, 14 workflows, 16 publications, 26 HTTP sources and 15 sinks. These
are inherited planning inventory counts, not coverage established by this repo's
smaller fixtures. Reconcile and pin the exact workload before making comparisons.

Use attributable authorized source or public synthetic equivalents of the same
obligations; do not copy private consumer policy or credentials. List any omitted
operation explicitly. The delivered small six-schema fixture does not by itself
qualify the complete six-domain application or protected workflows.

## Qualification sequence

1. **Freeze the experiment.** Record compiler commit, pure dependency archive,
   shared definition IDs, runtime/test-host commits, source/lock/SQL digests,
   toolchain, platform, hardware, resource budgets and selected fault schedules.
   Keep the frozen extraction comparison binary separate from the compatible
   runtime used for new language features.
2. **Compose and relocate.** Build the full nested multi-package application,
   independently build child targets, use an exact remote package/subdirectory
   and explicit local override, then rebuild offline. Compare emitted SQL and
   provenance under controlled identities. Source moves cannot rename durable
   objects; conflicting stateful versions and exhausted budgets reject.
3. **Execute without source.** Remove source repositories and execute emitted SQL
   through ordinary clients. Compare definitions, ordered refusals, rows, output
   counts and authority with hand-expanded equivalents. Exercise post-compilation
   revocation, reference non-escalation and direct-SQL private-storage denials.
4. **Migrate and recover.** Compare immutable history replay with fresh desired
   state under identical bindings. Cover dependency upgrades, destructive-change
   refusal, admitted transforms, drift, lost replies, restart and all three
   replacement policies. Changed compiler/source must not reinterpret old work.
5. **Test workflows and evidence.** Execute every inventoried command/workflow,
   unknown-effect path and required interruption schedule through the production
   emitter and host. Include source grammar, formatter, typed-core, selected
   formal-law/model and independent SQL comparisons with meaningful negative
   controls. Preserve retained failures and state whether correspondence covers
   selected traces or every finite edge.
6. **Publish the result.** Record commands, raw outputs, coverage denominator,
   incomplete/unsupported cases, premises and benchmark method. Promote actual
   supported behavior into guides/reference and retain the planning record.

## Measurements

Retain the original evaluation targets: more than 35% less duplication, check-only
compilation below 500 ms, and offline build/test replay coverage of all 26 commands
and 14 workflows below two seconds. These are unverified targets, not promises
or reasons to omit slow/failing cases.

Define duplication consistently across handwritten SQL, source and generated
output; exclude generated bytes from authoring effort but report them separately.
Measure clean/warm compilation, dependency capture/checking, formatter throughput,
SQL emission/reparse, host startup, execution and replay separately, plus the
complete end-to-end wall time. Record repeats, distributions, peak memory,
allocation/output bounds, cache state and timeouts. Never substitute a compile-only
measurement for build-and-test latency or a simulated schedule for durability.

## Documentation and release handoff

Provide a connected user journey from installation through modules, formatting,
dependencies, diagnostics, SQL inspection, migrations, tests and CI. Check every
published example against runnable source and actual failure/correction output.
Document embedding ownership/lifetimes and compiler/runtime compatibility. Keep
proposals out of runnable tutorials and roadmap sequencing out of current usage.

Milestone 4 owns native host execution, release artifact identity, handbook
navigation/hosting and distribution qualification. Feed the expanded supported
profile and compatibility evidence into that process; a documentation build or
cross-compilation is not native execution or live publication.

## Adjacent work and completion

Transit M17 may add optional AOT/specialization targets using this same build
graph and bound SQL semantics. It retains runtime query-engine/code-generation
ownership; agree artifact/ABI/cache contracts before adding a compiler adapter.
M22/M31 may consume neutral definition diffs, M24 extends formal coverage, and
M45 audits the broader SQL dialect. These are explicit handoffs, not a second
module system or permission to defer this roadmap's own correctness checks.

Complete only when the frozen inventory and required journeys pass at the stated
compatible revisions, measured targets have an explicit outcome, and outstanding
limits are published. A missed performance target remains open or requires a
reviewed change to the criterion; source extraction, merges and selected fixture
passes do not complete this milestone.
